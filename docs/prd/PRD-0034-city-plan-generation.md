# PRD-0034: 城市总规生成范式（City Plan Generation）

## Vision

把 `godot_citys` 的城市从「沿路撒建筑的均匀贴图」改成「有地理、有历史、有层次、可步行探索的地方」。

成功的样子：

- 玩家站在任意路口，能靠**地标、水岸、街道尺度**说出自己在哪一区。
- 城市有一条**河**、一段**水岸**、一个**老城核心**、一条**铁路与车站**、一个**市场广场**；它们解释了城市为什么长在这里。
- 街道有**连续街墙、窄巷、内院、广场**，不再是塔楼加草坪。
- 建筑按**时代语法**生成：老城小地块低层、中城装饰艺术、现代板楼、CBD 玻璃塔；只有地标塔允许收分。
- 至少一个 **1km² 垂直切片**可以步行体验：从水岸走到市场广场，再上到地标天台。

## 背景

v62 已经把建筑单体和街道家具重做了一遍，但用户反馈「平平无奇、没有欲望逛下去」。根因不是模型精度，而是：

1. 没有地理因果（河/海/山/铁路），城市是均匀撒出来的。
2. 只有路径，没有边缘/节点/地标（Kevin Lynch 五要素缺四个）。
3. 没有时间和阶层：地块语法、路网密度、材料全城一套。
4. 没有可玩性：楼进不去、屋顶上不去、没有可发现的内容。

本 PRD 定义新的**总规生成范式**：先地理，后城市，再做建筑。

## 需求

### REQ-0034-001 确定性总规计划

- **动机**：总规必须可复现、可缓存，否则 chunk 流式无法稳定。
- **范围**：`CityPlanGenerator` 以 `world_seed` 为唯一随机源，输出完整 `CityPlan` 字典；同一 seed 两次生成的结果哈希一致。
- **非目标**：不做运行时编辑/玩家改造。
- **验收**：同一 seed 连续生成两次，`plan_hash` 完全相等；缓存写入后重启再读，`plan_hash` 不变。

### REQ-0034-002 地形与水系

- **动机**：城市需要「为什么在这里」。
- **范围**：生成 1 条主河（或海岸线）、2~4 座缓丘、湿地/滩涂；提供 `height_at(x,z)` 与 `water_mask_at(x,z)`；道路与街区避开水面并顺应地形。
- **非目标**：不做真实水文模拟、不做潮汐。
- **验收**：主河折线长度 ≥ 3000m，河宽 40~120m；切片内水面覆盖 ≥ 2%；`height_at` 在河岸两侧连续（相邻 1m 采样高差 ≤ 2m，除堤岸）。

### REQ-0034-003 历史核心与生长轴

- **动机**：城市要有时间层，而不是同一天的复制品。
- **范围**：老城核心（渡口/城门）、2~3 条生长轴（古道→主干道）、铁路环线与 3~5 个车站；新区沿轴外扩。
- **非目标**：不做真实历史事件模拟。
- **验收**：`plan.history.core` 存在且落在河/海岸 800m 内；≥2 条生长轴从核心放射；≥1 条铁路折线闭合且 ≥3 个车站节点。

### REQ-0034-004 区域与街区语法

- **动机**：不同区域必须有不同**地块语法**，不是换颜色。
- **范围**：`downtown / commercial / residential / oldtown / industrial / waterfront` 六类；每类定义地块尺寸、退线、街墙率、巷弄宽度、院落概率；街区由路网切分，地块沿街细分。
- **非目标**：不做玩家可编辑地块。
- **验收**：10km 采样窗内每类区域占地 ≥ 3%（waterfront ≥ 2%）；1km 切片内至少出现 2 类区域且必须含 waterfront；抽样 100 个临街地块，≥ 70% 的立面落在人行道后 8m 内；oldtown 平均地块面宽 ≤ 12m，downtown ≥ 24m。

### REQ-0034-005 建筑时代语法与地标

- **动机**：同一套盒子换颜色解决不了「都像帝国大厦」和「都一样」。
- **范围**：4 个时代语法（oldtown / art_deco / modern / glass_cbd），每类有独立体量、层高、开窗、屋顶；3 个地标（超高层、双塔连桥、水岸塔），只有地标允许收分；地标有唯一 `landmark_id` 和地图标记。
- **非目标**：不改作者场景（汉堡店/枪店/咖啡馆/服务建筑/venue）。
- **验收**：抽样 100 栋建筑，≥ 95% 的 `era` 与所在区域匹配；3 个地标 `landmark_id` 唯一且最高者 ≥ 120m；非地标建筑中收分体量占比 ≤ 10%。

### REQ-0034-006 垂直切片与可步行性

- **动机**：先证明「想逛」，再推广全城。
- **范围**：以出生点为中心的 1km² 切片：水岸步道、市场广场、老城窄巷、1 个可进入底层 + 可上天台的地标；切片外回退 v62。
- **非目标**：不做完整室内装修、不做任务链。
- **验收**：4 个步行路径点（水岸/市场/窄巷/天台）各有一张自动截图；玩家可从地面走到地标天台（E2E 脚本断言到达高度 ≥ 建筑高度 90%）；切片外 chunk 的 `variant_id` 与 v62 基线一致。

### REQ-0034-007 性能与回退

- **动机**：60 FPS 是硬红线。
- **范围**：总规只生成一次并缓存；chunk 采样 O(1)；切片外走 v62 路径。
- **非目标**：不牺牲已有性能预算。
- **验收**：`test_city_chunk_setup_profile_breakdown` 通过（total ≤ 8500 usec）；`test_city_first_visit_performance_profile` 通过（mount ≤ 5500 usec）；切片外 profile signature 与基线一致。

## 约束

- 作者场景与 `building_id` / `inspection_payload` 链路不动。
- 共享导航 / 任务 / 地图 contract 不动；新地标接入现有 landmark 链路。
- 确定性：所有随机来自 seed 派生的哈希，不使用全局 RNG 状态。
- 性能：60 FPS = 16.67ms/frame；chunk setup 预算不变。

## 非目标

- 不引入外部美术资产或付费素材。
- 不做多人、不做存档改造。
- 不在本版做夜景/天气/人流 AI 的大改（留给 v64）。

## 术语

| 术语 | 含义 |
| --- | --- |
| CityPlan | 世界级总规数据（地形、历史、路网、区域、街区、地标） |
| District | 区域类型，决定地块语法与建筑时代 |
| Block | 由路网切出的街区 |
| Parcel | 街区沿街细分出的地块，承载一栋建筑 |
| Era | 建筑时代语法 |
| Slice | 1km² 垂直切片，本版唯一验收范围 |
